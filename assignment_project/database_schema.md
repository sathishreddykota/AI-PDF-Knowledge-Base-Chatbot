# Database & Vector Store Schema Design

This document details the data schemas used in the AI PDF Knowledge Base Chatbot system. The application leverages **MongoDB** for relational and conversational persistence and **ChromaDB** as the high-dimensional Vector Database for semantic search.

---

## 🍃 MongoDB Schema Design

MongoDB stores authentication details, uploaded file metadata, and conversation logs. The database contains three primary collections:

### 1. Users Collection
Stores administrative user accounts authorized to access the Admin Portal dashboard and manage the knowledge base.
- **Mongoose Model Name**: `User`
- **Collection Name**: `users`

| Field | Type | Required | Unique | Index | Description |
|---|---|---|---|---|---|
| `_id` | `ObjectId` | Yes | Yes | Yes | Primary key generated by MongoDB |
| `email` | `String` | Yes | Yes | Yes | Admin login email address |
| `password` | `String` | Yes | No | No | BCrypt hashed password |
| `createdAt` | `Date` | Yes | No | No | Automatically populated creation timestamp |
| `updatedAt` | `Date` | Yes | No | No | Automatically populated modification timestamp |

---

### 2. Documents Collection
Maintains metadata for uploaded PDF files, tracking file sizes, processing states, and raw file buffers for reprocessing capabilities.
- **Mongoose Model Name**: `PdfDocument`
- **Collection Name**: `pdfdocuments`

| Field | Type | Required | Default | Index | Description |
|---|---|---|---|---|---|
| `_id` | `ObjectId` | Yes | N/A | Yes | Primary key generated by MongoDB |
| `filename` | `String` | Yes | N/A | No | Original name of the uploaded PDF |
| `size` | `Number` | Yes | `0` | No | File size in bytes |
| `status` | `String` | Yes | `'uploading'` | No | Processing status: `'uploading'`, `'processing'`, `'completed'`, `'failed'` |
| `uploadDate` | `Date` | Yes | `Date.now` | No | Timestamp when the document was uploaded |
| `totalChunks` | `Number` | Yes | `0` | No | Number of semantic chunks created by the text splitter |
| `metadata` | `Object` | Yes | `{}` | No | Arbitrary metadata key-value storage |
| `fileData` | `String` | No | N/A | No | Base64-encoded PDF binary file data (omitted if file > 10MB to respect BSON limits) |
| `createdAt` | `Date` | Yes | N/A | No | Automatically populated creation timestamp |
| `updatedAt` | `Date` | Yes | N/A | No | Automatically populated modification timestamp |

---

### 3. Chats Collection
Logs individual chat queries, AI responses, source document citations, and follow-up question suggestions.
- **Mongoose Model Name**: `Chat`
- **Collection Name**: `chats`

| Field | Type | Required | Default | Index | Description |
|---|---|---|---|---|---|
| `_id` | `ObjectId` | Yes | N/A | Yes | Primary key generated by MongoDB |
| `sessionId` | `String` | Yes | N/A | Yes | Unique chat session UUID (used for context retrieval) |
| `question` | `String` | Yes | N/A | No | Plain text query submitted by the public user |
| `answer` | `String` | Yes | N/A | No | Grounded response generated by the RAG model |
| `sources` | `Array` | Yes | `[]` | No | List of source documents used: `[{ filename: String, pageNumber: Number }]` |
| `suggestedQuestions` | `Array` | Yes | `[]` | No | List of suggested follow-up questions generated by Gemini |
| `timestamp` | `Date` | Yes | `Date.now` | No | Creation timestamp for chronological session sorting |
| `createdAt` | `Date` | Yes | N/A | No | Automatically populated creation timestamp |
| `updatedAt` | `Date` | Yes | N/A | No | Automatically populated modification timestamp |

---

## 📐 Vector Store Schema Design (ChromaDB)

ChromaDB is used to store high-dimensional vector embeddings generated from PDF chunks. This allows the system to perform fast similarity searches to find context relevant to a user's question.

### Collection Layout
- **Collection Name**: `pdf_knowledge_base`
- **Distance Metric**: Cosine Similarity (`"hnsw:space": "cosine"`)
- **Embedding Model**: Google Gemini (`models/gemini-embedding-001`)
- **Vector Dimensions**: `3072`

Each record inside the collection contains:

1. **ID**: A unique string formatted as: `{document_id}_chunk_{chunk_index}`
2. **Embedding**: The `3072`-dimensional float vector generated from the chunk text.
3. **Document Text**: The raw semantic slice of text extracted from the PDF page.
4. **Metadata Object**: Used to filter searches and map vector results back to sources:
   - `document_id`: The matching MongoDB `_id` of the parent document (used for vector deletion on file delete).
   - `filename`: Original name of the PDF (used to show source citations).
   - `page_number`: 1-based page number where the chunk text resides.
   - `chunk_index`: Sequence order of the chunk in the document.
